# 微服务架构基础

## 核心原则

1. 单一职责: 每个服务只做一件事
2. 独立部署: 服务间独立发布
3. 去中心化: 每个服务独立数据库
4. 容错设计: 服务故障不影响整体

## 通信方式

- 同步: REST API, gRPC
- 异步: 消息队列 (Kafka, RabbitMQ)
- 事件驱动: Event Bus

## API 网关

统一入口，负责路由、认证、限流：

```
客户端 → API 网关 → 服务A/服务B/服务C
```

## 与单体架构对比

| 维度 | 单体 | 微服务 |
|:--|:--|:--|
| 复杂度 | 低 | 高 |
| 扩展性 | 差 | 好 |
| 部署 | 简单 | 复杂 |
